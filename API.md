# Як працює API

API — це посередник між вебінтерфейсом і базою даних. Angular надсилає HTTP-запити через `HttpClient`, ASP.NET Core обробляє їх, а Entity Framework Core читає або змінює дані в PostgreSQL.

## Як проходить запит

Під час локальної розробки:

1. Інтерфейс працює на `http://localhost:4200`.
2. `CrmApiService` у `frontend/src/app/crm-api.service.ts` надсилає HTTP-запити, наприклад `GET /CrmTask`.
3. Angular proxy з `frontend/proxy.conf.json` пересилає ці запити до API на `http://localhost:5283`. Тому браузеру не потрібно окремо дозволяти CORS для локальної розробки.
4. Контролер ASP.NET Core перевіряє запит і працює з відповідною таблицею через `CrmDbContext`.
5. PostgreSQL зберігає або повертає дані. API надсилає результат назад у браузер у форматі JSON.

Щоб усе працювало, запустіть API та Angular у двох окремих терміналах. Інструкція зі запуску є у [README.md](./README.md).

## Адреса API

Локальна адреса API: `http://localhost:5283`.

Основні маршрути:

| Маршрут | Для чого потрібен |
| --- | --- |
| `/CrmTask` | Перегляд і керування завданнями |
| `/Department` | Перегляд і керування відділами |
| `/Status` | Перегляд доступних статусів |

ID завдань, відділів і статусів — UUID, наприклад `ccd1e516-da30-4d18-93c8-b97581df29e5`.

## Завдання

| Метод і маршрут | Дія | Успішна відповідь |
| --- | --- | --- |
| `GET /CrmTask` | Отримати всі завдання | `200 OK` і масив завдань |
| `GET /CrmTask/{id}` | Отримати завдання за UUID | `200 OK`; якщо не знайдено — `404 Not Found` |
| `POST /CrmTask` | Створити завдання | `201 Created` і створене завдання |
| `PUT /CrmTask/{id}` | Повністю оновити завдання | `204 No Content` |
| `DELETE /CrmTask/{id}` | Видалити завдання | `204 No Content` |

Приклад тіла запиту для `POST /CrmTask`:

```json
{
  "name": "Підготувати звіт",
  "status_id": "5acbe650-d38a-4821-90da-ec8e3a7b0649",
  "department_id": "01778524-fe84-4630-a256-8eb579801ffd",
  "assignee": "Іван Петренко",
  "deadline": "2026-10-20",
  "description": "Зібрати дані за місяць",
  "cancel_reason": null
}
```

Не передавайте `id` під час створення: його генерує API. Дати передаються у форматі `YYYY-MM-DD`. `status_id` і `department_id` можуть бути `null`, але якщо вказаний UUID, він має існувати у відповідній таблиці.

Статус «Скасовано» вимагає непорожнє поле `cancel_reason`. Його максимальна довжина — 250 символів. Якщо причина відсутня або UUID статусу чи відділу невідомий, API повертає `400 Bad Request` з описом помилки. Для `PUT` значення `id` у URL та в тілі запиту мають збігатися.

## Відділи

| Метод і маршрут | Дія | Успішна відповідь |
| --- | --- | --- |
| `GET /Department` | Отримати всі відділи | `200 OK` і масив відділів |
| `GET /Department/{id}` | Отримати відділ за UUID | `200 OK`; якщо не знайдено — `404 Not Found` |
| `POST /Department` | Створити відділ | `201 Created` і створений відділ |
| `PUT /Department/{id}` | Змінити назву відділу | `204 No Content` |
| `DELETE /Department/{id}` | Видалити відділ | `204 No Content` |

Тіло для створення або оновлення відділу:

```json
{
  "id": "d2c9f095-8e4c-498a-802a-68c220dbe1bd",
  "name": "Відділ закупівель"
}
```

Для `POST` поле `id` можна не передавати — його згенерує сервер. Відділ, до якого прив’язані завдання, видалити не можна: API поверне `409 Conflict`.

## Статуси

| Метод і маршрут | Дія | Успішна відповідь |
| --- | --- | --- |
| `GET /Status` | Отримати всі доступні статуси | `200 OK` і масив статусів |
| `GET /Status/{id}` | Отримати статус за UUID | `200 OK`; якщо не знайдено — `404 Not Found` |

Список статусів фіксований: `Новий`, `В роботі`, `Виконано`, `Скасовано`. API дозволяє переглядати його, але не створювати, змінювати чи видаляти статуси. Щоб дізнатися UUID потрібного статусу, виконайте `GET /Status`.

## Перевірка через `curl`

Отримати статуси, відділи й завдання:

```bash
curl http://localhost:5283/Status
curl http://localhost:5283/Department
curl http://localhost:5283/CrmTask
```

Створити завдання: спочатку візьміть справжні UUID статусу й відділу з відповідей попередніх запитів і підставте їх замість `STATUS_UUID` та `DEPARTMENT_UUID`:

```bash
curl -i --request POST \
  --header 'Content-Type: application/json' \
  --data '{"name":"Підготувати звіт","status_id":"STATUS_UUID","department_id":"DEPARTMENT_UUID","deadline":"2026-10-20","description":"Зібрати дані за місяць"}' \
  http://localhost:5283/CrmTask
```

## База даних під час першого запуску

Під час запуску API створює таблиці в налаштованій порожній базі даних і завантажує приклади з CSV-файлів у папці `testData`. Якщо таблиці вже містять дані, імпорт пропускається, щоб не перезаписати їх.
